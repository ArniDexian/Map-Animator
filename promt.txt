# Техническое задание: Консольная утилита для анимации трека на карте (Python + OpenCV)

Необходимо написать надежный Python-скрипт `animate_map.py` и конфигурационный файл `config.json` для создания видео-анимации прохождения маршрута по карте. 

Скрипт принимает два изображения: чистую карту (`clean_map`) и карту с нарисованным синим треком и круговыми маркерами остановок (`track_map`). Скрипт автоматически выделяет трек, строит одномерную (1D) траекторию без петель и возвратов, находит круговые маркеры (A, B, C...), рассчитывает хронометраж в секундах и рендерит MP4-видео.

---

### 1. Архитектура и требования к конфигурации (`config.json`)

Файл конфигурации должен иметь следующую структуру по умолчанию:

{
  "inputs": {
    "clean_map": "clean_map.jpg",
    "track_map": "track_map.jpg"
  },
  "output": {
    "video_path": "output_animation.mp4",
    "fps": 30,
    "codec": "mp4v",
    "resolution": null
  },
  "mode": "redraw",
  "timing": {
    "initial_delay_sec": 1.0,
    "track_duration_sec": 4.0,
    "pause_on_waypoints": true,
    "waypoint_pause_duration_sec": 1.2,
    "final_delay_sec": 2.0
  },
  "circle_detection": {
    "min_circle_radius_px": 8.5
  },
  "reveal_settings": {
    "line_brush_radius": 12,
    "waypoint_brush_radius": 22
  },
  "redraw_settings": {
    "line_color_bgr": [255, 122, 0],
    "line_thickness": 10,
    "marker_color_bgr": [255, 122, 0],
    "marker_text_color_bgr": [255, 255, 255],
    "marker_radius": 16,
    "marker_font_scale": 0.55,
    "marker_font_thickness": 2
  },
  "hsv_blue_range": {
    "lower": [90, 50, 50],
    "upper": [130, 255, 255]
  },
  "logging": {
    "file": "animate_map.log",
    "level": "INFO"
  }
}

### 2. Ключевая алгоритмическая логика (`animate_map.py`)

#### Шаг 1: Выделение маски трека и заполнение разрывов
1. Найти разницу между `clean_map` и `track_map` через `cv2.absdiff` + порог градиента (`gray > 15`).
2. Применить HSV-маску синего цвета (`hsv_blue_range`) для вычленения только линии трека и синих кружков.
3. **ВАЖНО (Устранение разрывов букв):** Внутри кружков есть белые буквы (A, B, C...). Они создают разрывы в синей маске. Применить морфологическое закрытие (`cv2.morphologyEx` с эллиптическим ядром 15x15), чтобы полностью залить внутренность кружков и сделать граф связным.

#### Шаг 2: Извлечение строго одномерной 1D-траектории (без петель и бега туда-обратно)
1. Выполнить скелетизацию маски (`skimage.morphology.skeletonize`).
2. Построить 8-связный граф точек через `networkx.Graph`.
3. Обрезать тупиковые микро-ответвления (spur pruning) и взять наибольший связный компонент графа.
4. Найти две крайние точки линии (степень узла == 1). Автоматически определить стартовую точку A (например, самая южная/нижняя точка по координате Y).
5. Построить **единственный кратчайший 1D-путь** от начальной точки до конечной. Путь не должен содержать циклов, разворотов или скачков.
6. Сгладить координаты пути фильтром Гаусса (`scipy.ndimage.gaussian_filter1d`, sigma=1.2).
7. Рассчитать массив накопленных длин (кумулятивную дистанцию в пикселях вдоль пути).

#### Шаг 3: Детектирование и топологическая сортировка маркеров (A, B, C, D...)
1. Применить преобразование расстояний (`cv2.distanceTransform`) к закрытой маске трека.
2. Найти локальные максимумы (пики толщины), где радиус `>= min_circle_radius_px` (по умолчанию `8.5`px). Это позволяет четко отделить круглые маркеры от поворотов и изгибов самой линии.
3. Проецировать каждый найденный центр кружка на 1D-траекторию и определить его координату пройденного расстояния (в пикселях от старта).
4. **Сортировка:** Отсортировать все найденные маркеры строго по возрастанию пройденного расстояния вдоль траектории.
5. Присвоить маркерам буквы по порядку: A, B, C, D, E и т.д.

#### Шаг 4: Расчет хронометража и кадров
Хронометраж вычисляется в секундах, а не в пикселях:
- `initial_frames` = `initial_delay_sec` * `fps`
- `motion_frames` = `track_duration_sec` * `fps`
- `wp_pause_frames` = `waypoint_pause_duration_sec` * `fps` (для промежуточных точек между стартом и финишем)
- `final_frames` = `final_delay_sec` * `fps`
- `total_duration` = `initial_delay_sec` + `track_duration_sec` + (Количество_промежуточных_точек * `waypoint_pause_duration_sec`) + `final_delay_sec`
- `total_frames` = `round(total_duration * fps)`

#### Шаг 5: Рендеринг кадров

##### Режим `redraw` (Векторная отрисовка):
1. На чистую карту `clean_map` наносится сглаженная полилиния трека (`cv2.polylines`) толщиной `line_thickness` и цветом `line_color_bgr`.
2. По мере достижения маркеров на карту поверх линии отрисовываются векторные кружки:
   - Внешнее белое кольцо (`marker_radius + 2`).
   - Синий закрашенный круг (`marker_radius`).
   - Буква (A, B, C...), выровненная строго по центру круга с помощью `cv2.getTextSize`.

##### Режим `reveal` (Проявление оригинала):
1. Накапливается маска мазка.
2. При движении вдоль линии используем `line_brush_radius`.
3. В районе координат кружков кисть автоматически расширяется до `waypoint_brush_radius`, чтобы полностью проявлять маркер с запасом по ширине.
4. Кадр создается путем альфа-смешивания `clean_map` и `track_map` по созданной маске.

### 3. Требования к исполнению и консольному интерфейсу
- CLI аргумент `--config` для передачи пути к JSON-файлу.
- Индикатор прогресса генерации через `tqdm`.
- Подробное логирование всех этапов в файл `animate_map.log` и консоль.
- Возможность масштабирования итогового видео через параметр `"resolution": [Width, Height]` (если `null` — сохранять оригинальный размер).
- Корректная обработка ошибок (проверка наличия файлов, совпадения размеров карт и т.д.).

# Map Animator

[English](README.md) · **Русский**

Превращает две картинки карты в видео: по карте «проезжает» синий трек от точки A до последней остановки, а по пути появляются кружки с буквами A, B, C…

![Чистая карта + та же карта с треком → Map Animator → анимированное видео](docs/assets/hero.gif)

* **Вход:** **чистая карта** и **та же карта с нарисованным синим треком и круглыми маркерами остановок** (например, скриншот с маршрутом).
* **Выход:** **MP4-видео** (по умолчанию 16:9, H.264/H.265 почти без потерь, до 4K).
* **Два способа работы:** приложение для macOS с окном (перетащили карты, настройки, превью, встроенный плеер) или консольная утилита для скриптов.

> Демо-карты в `examples/` созданы синтетически (`tools/make_demo.py`) и не содержат чужих картографических данных. Свои карты используйте с учётом условий их поставщика.

## 1. Установка

**Требования:** Mac с Apple Silicon (M1 и новее), macOS 13+, интернет при первом запуске. Python 3 входит в «Инструменты командной строки» Apple (macOS предложит их поставить, если их нет; у всех, кто когда-либо пользовался `git`, они уже есть).

### A. Из образа диска (рекомендуется)

1. Возьмите `Map-Animator-<версия>.dmg` (релиз на GitHub или соберите сами: `./make_dmg.sh`).
2. Откройте его и **перетащите *Map Animator* на *Applications***.
3. В первый раз откройте приложение **правым кликом → Открыть → Открыть** (оно не подписано Apple). Если macOS всё равно отказывает: `xattr -dr com.apple.quarantine "/Applications/Map Animator.app"`.
4. При первом запуске приложение увидит, что пакеты Python ещё не установлены, спросит *«Установить сейчас?»* и откроет Terminal с пошаговым установщиком (проверка Python, создание окружения, установка OpenCV, SciPy, scikit-image, ffmpeg… — 1–3 минуты). По окончании приложение продолжит само.

### B. Из исходников (для консольной утилиты и разработчиков)

```bash
git clone <этот репозиторий>
cd <папка>
./install.command            # пошагово: проверка Python, .venv, пакеты, самопроверка
./build_app.sh               # собрать Map Animator.app (или ./make_dmg.sh для образа диска)
```

**Какой Python используется.** Установщик не ставит свой Python: он ищет те, что уже есть на вашем Mac (Homebrew, python.org, pyenv, системный), оставляет подходящие (3.9+, действительно работающие) и берёт самый новый из них, но не выше 3.13 (он печатает, что нашёл и что выбрал). Выбрать вручную: `./install.command --python=/путь/к/python3` или `MAP_ANIMATOR_PYTHON=…`. Дальше он работает только с созданным окружением (`…/bin/python -m pip`), поэтому то, как у вас называются `python` / `python3` / `pip3`, значения не имеет.

Флаги `install.command`: `--check` (только проверить), `--yes` (без вопросов), `--no-open`, `--python=ПУТЬ`. Консольная утилита и `python ui.py` используют `.venv` из папки проекта. **Приложение само находит свой Python**: сначала собственное окружение (`~/Library/Application Support/Map Animator/venv`), потом `.venv` рядом с исходниками, из которых оно собрано (только для локальных сборок — в образах диска личных путей нет), потом любой Python на Mac, где уже есть все пакеты (Homebrew, python.org, инструменты Xcode). Установку оно предлагает, только если ни один вариант не подходит полностью. Что оно проверило и выбрало, записано в `~/Documents/Map Animator/logs/app.log`.

### Где лежат ваши файлы

| Что | Где |
|---|---|
| **Готовые видео** | `~/Documents/Map Animator/` |
| Debug-картинки (`--debug`) и логи | `~/Documents/Map Animator/debug/`, `~/Documents/Map Animator/logs/` |
| Окружение Python, настройки, стили, загруженные карты | `~/Library/Application Support/Map Animator/` (скрытая папка; окружение ≈ 700 МБ, поэтому оно не в «Документах»: они могут синхронизироваться с iCloud) |
| Сама программа (код, страница, конфиг, документация) | внутри `Map Animator.app`; чтобы обновить, замените приложение — данные не затрагиваются |

*Удаление:* удалите приложение, `~/Library/Application Support/Map Animator/` и, если хотите, `~/Documents/Map Animator/`. В папке с исходниками (прямой запуск `ui.py` / `animate_map.py`) всё остаётся внутри папки проекта (`output/`, `debug/`, `logs/`).

## 2. Быстрый старт (приложение)

1. Откройте **`Map Animator.app`** двойным кликом.
2. Перетащите на окно **обе карты** — чистую и с треком. Можно оба файла сразу (файл со словом `track` в имени считается картой с треком), можно по одному, а можно кликнуть по полю и выбрать файл. *Нет своих карт? Возьмите `examples/demo_clean_map.jpg` и `examples/demo_track_map.jpg`.*
3. Через секунду приложение проверит карты и покажет, сколько найдено кружков и какой будет длительность видео.
4. При желании поменяйте настройки (всё запоминается).
5. Нажмите **«Генерировать»**. Внизу идёт полоса прогресса с оставшимся временем.
6. Готовое видео появляется в списке **«Результаты»**: **▶ Смотреть** (встроенный плеер) и **Показать в Finder**. Файлы лежат в `~/Documents/Map Animator/` с временной меткой в имени, например `animation_redraw_20261017_143332.mp4`; новые файлы старые не перезаписывают.

Закрыть окно — значит выйти из приложения. Если в этот момент идёт генерация, приложение дождётся её конца и выйдет само (`⌘Q` спросит подтверждение и прервёт генерацию).

### Если приложение не запускается
* macOS один раз спросит доступ к папке *«Документы»* (там лежат ваши видео): нажмите **«Разрешить»** или выдайте доступ в *Системные настройки → Конфиденциальность и безопасность → Файлы и папки* / *Полный доступ к диску*.
* Логи: `~/Documents/Map Animator/logs/ui_server.log` (запуск сервера) и `…/logs/animate_map_*.log` (каждая генерация).
* Иконка в Finder не обновилась — выполните один раз `killall Dock Finder`.
* На другом Mac что-то выглядит или работает иначе (в списке нет системных шрифтов, элемент ничего не делает…): нажмите **«Диагностика»** в верхней строке. Приложение соберёт отчёт (версии macOS и Python, установленные пакеты, какие шрифты найдены и почему нет, видеокодер, последние строки логов, ошибки JavaScript страницы), сохранит его в `~/Documents/Map Animator/logs/diagnostics.txt` и даст скопировать; отправьте этот текст тому, кто сопровождает приложение.
* Вид элементов (выпадающие списки, ползунки, галочки) рисует сама страница, поэтому он одинаков на любой версии macOS.

## 3. Приложение: что на экране

### Карты
Два поля для перетаскивания. После загрузки обеих карт идёт **автопроверка**:
* **Перепутаны местами** (трек нарисован на «чистом» файле) — карты **автоматически меняются местами**, об этом пишется сообщение.
* **Трека нет вообще** (карты одинаковые или трек не синий) — ошибка, кнопка «Генерировать» недоступна.
* **Карты не совпадают** (разные картинки или одна сдвинута/масштабирована) — ошибка с процентом различий. Вне трека карты должны быть идентичны.
* **Разные размеры** — ошибка.

### Основное
| Поле | Что делает |
|---|---|
| Режим | `redraw` (по умолчанию) — линия и маркеры рисуются заново на чистой карте; `reveal` — проявляется оригинальная картинка с треком |
| FPS | 24, 25, 30, 48, 50, 60 |
| Разрешение | «Как у карты» (вся карта, без кадрирования), «Исходный масштаб, кадр 16:9» или 4K / 1440p / 1080p / 720p / 480p (всегда 16:9) |
| Кодек | H.264 (по умолчанию, играет везде), H.265 (компактнее, кодируется дольше), MPEG-4 (старый) |
| Качество | Максимальное (почти без потерь) / Высокое / Сбалансированное |
| Паузы | до первого маркера; перед стартом движения; на промежуточных остановках; в конце |
| Длительность движения | время, за которое «точка» проходит весь трек |

Под полями показана **полная длительность видео** с разбивкой: `1 (до кружка) + 1 (перед стартом) + 4 (движение) + 3 × 1.2 (паузы на точках) + 2 (финал)`. Дробные числа можно вводить и через точку, и через запятую.

**Кадр 16:9.** Видео всегда 16:9: из карты вырезается самая большая область с таким соотношением, по центру трека. Если трек не помещается, в логе будет предупреждение, а края срежутся. Хотите всю карту — выберите «Как у карты».

### Режим `redraw`: линия и маркеры
* Вверху — **превью** (линия с кружком и буквой). Если загружена карта, фон — кусочек этой карты в реальном масштабе.
* **Стили** — сохранённые наборы настроек. Встроенный **«По умолчанию»** (голубой) нельзя удалить или перезаписать. Свой стиль: настройте → «Сохранить стиль» → имя (предлагается автоматически). Одинаковый стиль второй раз не сохраняется. Выбор стиля применяет все его значения; «Удалить стиль» удаляет только свои стили.
* Поля: цвет и толщина линии (ползунок + число), цвет и радиус кружка, **обводка кружка** (толщина, 0 = без обводки; цвет), цвет буквы, шрифт (SF Pro — системный шрифт macOS — и другие системные), его начертание и размер, переключатель «Подгонять размеры под картинку».

> **Подгонять размеры под картинку.** Значения по умолчанию рассчитаны на картинку, где радиус кружка около 16 px. Если на вашей карте кружки крупнее, все размеры (толщина линии, радиус, обводка, шрифт) умножаются на отношение «реальный радиус / заданный». Выключите переключатель, чтобы использовать числа буквально.

### Режим `reveal`: кисти
Оригинальная картинка проявляется кистью, идущей по пути. Пустые поля — автоматически: кисть линии равна реальной толщине линии плюс запас; кружок проявляется целиком вместе с белой обводкой; линия подходит к кружку вплотную, и кружок появляется ровно в этот момент.

### Дополнительно: поиск трека и маркеров
Диапазон синего цвета (HSV), минимальный радиус кружка, обрезка коротких ответвлений, сглаживание пути, порог разницы карт. Менять нужно, только если трек не синий.

### Превью до генерации
Кнопка **«Превью»** (слева от «Генерировать») открывает окно, в котором анимация рисуется **на лету**, без кодирования видео: вы видите настоящую карту, линию и маркеры так, как их покажет видео (те же рендереры, только в уменьшенном размере). Пауза/продолжить, ползунок перемотки, скорость 0,25×–2×. Превью берёт **текущие настройки**; чтобы изменить их, закройте окно превью (приложение остаётся открытым), поменяйте и откройте снова. Кнопка **«Генерировать»** в окне превью сразу запускает видео. Кадр рисуется ≈ 10 мс в `redraw` и ≈ 50 мс в `reveal`, поэтому перемотка мгновенная.

### Результаты и плеер
* Список готовых видео из `output/`. У каждого есть **▶ Смотреть** и **Показать в Finder**. Кнопка **«Очистить»** (видна, только если есть файлы; просит подтверждение) удаляет все видео, debug-картинки и логи.
* **Плеер:** пауза/продолжить (пробел или клик по видео), плавный ползунок перемотки, скорость 0,25×–2×, «Показать в Finder», «Открыть во внешнем плеере» и **«Удалить»** (закрывает плеер и удаляет это видео). Закрыть — `Esc` или клик вне окна.

### Прочее
* **RU/EN** — язык интерфейса (по умолчанию как в системе; выбор запоминается).
* **A− / A+** (или `⌘+`, `⌘−`, `⌘0`) — размер текста интерфейса.
* **Документация** — открывает это описание в отдельном окне (есть и в меню: *Map Animator → Документация*).
* **Сбросить настройки** — вернуть значения из `config.json`.
* Все настройки, стили, язык и размер текста хранятся в `ui_settings.json` и возвращаются при следующем запуске.

## 4. Консольная утилита

```bash
.venv/bin/python animate_map.py --config config.json            # обычный запуск
.venv/bin/python animate_map.py --config config.json --debug    # + картинки маски и пути в папку debug/
```

* Читает карты из `inputs.clean_map` / `inputs.track_map`, пишет видео в `output.video_path`, лог — в `logging.file`. Относительные пути считаются от папки, где лежит конфиг.
* Показывает прогресс-бар (в терминале) или строки «N%» каждые 5% (если вывод перенаправлен).
* Код возврата: `0` — успех, `1` — ожидаемая ошибка (нет файла, карты не совпадают, нет трека…), `2` — непредвиденная.

Попробовать на демо-картах: скопируйте `config.json`, укажите в `inputs.clean_map` / `track_map` файлы `examples/demo_clean_map.jpg` / `examples/demo_track_map.jpg` и запустите команду выше.

### Справочник `config.json`

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `inputs.clean_map`, `inputs.track_map` | `clean_map.jpg`, `track_map.jpg` | входные файлы |
| `inputs.auto_swap` | `true` | менять карты местами, если трек на «чистой» (иначе — ошибка) |
| `output.video_path` | `output/output_animation.mp4` | куда писать видео |
| `output.fps` | `30` | кадров в секунду |
| `output.codec` | `avc1` | `avc1` (H.264), `hvc1` (H.265), `mp4v` (MPEG-4) |
| `output.quality` | `max` | `max` / `high` / `balanced` (CRF 8/13/19 для H.264; 10/15/21 для H.265) |
| `output.resolution` | `null` | `[ширина, высота]` итогового видео; `null` — исходный размер кадра |
| `output.aspect` | `[16, 9]` | соотношение сторон кадра; `null` — не кадрировать, взять всю карту |
| `output.debug_dir` | `debug` | куда класть промежуточные картинки при `--debug` |
| `mode` | `redraw` | `redraw` или `reveal` |
| `timing.first_marker_delay_sec` | `1.0` | чистая карта до появления кружка A |
| `timing.initial_delay_sec` | `1.0` | кружок A стоит неподвижно до начала движения |
| `timing.track_duration_sec` | `4.0` | время движения по всему треку |
| `timing.pause_on_waypoints` | `true` | останавливаться на промежуточных точках |
| `timing.waypoint_pause_duration_sec` | `1.2` | длина остановки |
| `timing.final_delay_sec` | `2.0` | пауза в конце |
| `circle_detection.min_circle_radius_px` | `8.5` | нижний порог радиуса кружка (реальный порог ещё и ≥ 1,7 × полуширина линии) |
| `reveal_settings.line_brush_radius` | `null` | радиус кисти линии; `null` — авто |
| `reveal_settings.line_brush_margin_px` | `2` | запас кисти сверх реальной толщины линии |
| `reveal_settings.waypoint_brush_radius` | `null` | радиус диска маркера; `null` — измеряется по картинке |
| `redraw_settings.line_color_bgr`, `.line_thickness` | `[255,122,0]`, `10` | цвет (**BGR**!) и толщина линии |
| `redraw_settings.marker_color_bgr`, `.marker_radius` | `[255,122,0]`, `16` | цвет и радиус кружка |
| `redraw_settings.marker_outline_px`, `.marker_outline_color_bgr` | `2`, `[255,255,255]` | обводка кружка (0 — нет) |
| `redraw_settings.marker_text_color_bgr` | `[255,255,255]` | цвет буквы |
| `redraw_settings.marker_font_path`, `.marker_font_index`, `.marker_font_variation`, `.marker_font_size_px` | SF Pro, `0`, `Bold`, `16` | системный шрифт для букв; `marker_font_path: null` — встроенный шрифт OpenCV (`marker_font_scale`, `marker_font_thickness`) |
| `redraw_settings.auto_scale_drawing` | `true` | подгонять размеры под размер кружков на карте |
| `hsv_blue_range.lower/upper` | `[90,50,50]` / `[130,255,255]` | диапазон «синего» в HSV |
| `path_settings.spur_length_px` | `25` | ответвления короче обрезаются |
| `path_settings.smooth_sigma` | `1.2` | сглаживание траектории (гауссов фильтр) |
| `path_settings.diff_threshold` | `15` | порог различия пикселей двух карт |
| `path_settings.max_mismatch_fraction` | `0.01` | допустимая доля отличий вне трека; больше — ошибка «карты не совпадают» |
| `logging.file`, `logging.level` | `logs/animate_map.log`, `INFO` | лог |

Цвета в конфиге — **BGR** (порядок OpenCV), в приложении — обычные RGB; приложение конвертирует само.

# Технические детали

## 6. Архитектура

Три вида мест (`ui.py` берёт их из окружения, которое задаёт приложение): `APP_DIR` — ресурсы только для чтения (код, страница, `config.json`, документация; в приложении это `Contents/Resources/app`), `DATA_DIR` — внутренние данные (`MAP_ANIMATOR_DATA`, по умолчанию Application Support; в папке с исходниками — папка проекта), `HOME_DIR` — то, что видит пользователь (`MAP_ANIMATOR_HOME`, по умолчанию `~/Documents/Map Animator`: видео прямо в папке, `debug/`, `logs/`). Без этих двух переменных всё остаётся в папке проекта — так работают разработка и тесты.

```
Map Animator.app (SwiftUI)
 ├─ предпроверка: .venv есть и в нём все пакеты? нет → предлагает install.command в Terminal
 ├─ запускает:  .venv/bin/python ui.py --no-window            (сервер 127.0.0.1:8765)
 ├─ окно = WKWebView → http://127.0.0.1:8765/                 (ui_static/index.html)
 └─ окно «Документация» → http://127.0.0.1:8765/docs          (этот README на языке интерфейса)

ui.py
 ├─ пишет config_ui.json и запускает:  animate_map.py --config config_ui.json  (подпроцесс)
 ├─ читает его вывод построчно → прогресс/ETA для страницы
 └─ раздаёт страницу, API, видео (с Range) и документацию

animate_map.py  → output/*.mp4
```

Интерфейс **ничего не знает об алгоритме**: он только собирает конфиг и запускает скрипт, как это сделал бы человек в консоли. Два места, где `ui.py` импортирует `animate_map` и вызывает его напрямую, — предпроверка (`/api/analyze`, шаги 0–3, ≈ 0,3 с) и **превью**, которое использует класс `Scene` (ниже). Поэтому алгоритм можно менять независимо от интерфейса.

### Объект `Scene` (основной API `animate_map.py`)

```python
scene = animate_map.Scene.prepare(cfg, clean_bgr, track_bgr)   # шаги 0–4, выполняются один раз
scene.n_frames, scene.fps, scene.native_size, scene.markers     # факты о таймлайне
img = scene.render(i, (w, h))                                   # любой кадр i, нужного размера, BGR
```

`run()` (кодирование) и превью используют его оба, поэтому расходиться они не могут. Кадры `redraw` независимы; кадры `reveal` накапливают маску кисти, поэтому запрос кадра раньше предыдущего пересобирает маску (`RevealRenderer.reset`). `Scene` потокобезопасна (по одному кадру за раз); сервер держит в памяти две последние сцены.

## 7. Алгоритм (`animate_map.py`)

Шаги пронумерованы так же, как в логе (`[n/5]`).

0. **Проверка входа** (`check_inputs`): считает пиксели «синее и отличающееся» для обоих порядков файлов — если больше у «чистой», карты меняются местами. Затем различия вне трека (маска трека, расширенная на 41 px): больше `max_mismatch_fraction` — ошибка. Откалибровано на реальных картах: у правильной пары 0 %, даже сдвиг на 2 px даёт ≈ 25 %.
1. **Маска трека** (`extract_track_mask`): `absdiff` двух карт (> порога) AND HSV-маска синего; морфологическое закрытие эллипсом 15×15 заливает буквы внутри кружков; мелкие компоненты (< 20 % от самой большой) отбрасываются.
2. **Одномерный путь** (`extract_path`): скелетизация → 8-связный граф → обрезка коротких ответвлений → наибольшая компонента → два самых удалённых друг от друга узла (двойной обход Дейкстры) → кратчайший путь; начало **A — самая южная** точка. Путь сглаживается гауссом; считается накопленная длина. Концы продлеваются до центров крайних маркеров.
3. **Маркеры** (`detect_markers`): distance transform маски; порог радиуса `max(min_circle_radius_px, 1.7 × медианная полуширина линии)` отличает кружки от изгибов линии независимо от масштаба картинки. Центры проецируются на путь, маркеры сортируются по пройденному расстоянию → A, B, C… Затем `trim_tails` отрезает «хвосты» скелета за крайними кружками и ставит первую и последнюю точки пути ровно в их центры.
4. **Расписание кадров** (`build_schedule`): список `(расстояние_по_пути, число_показанных_маркеров)` на каждый кадр. Кружок появляется, когда линия доходит до его **края** (расстояние минус радиус); остановка — на центре.
5. **Рендер** и кодирование. Кадры с одинаковым состоянием (паузы) не пересчитываются.

### Режимы рендера
* **`redraw`** — `polylines` по сглаженному пути на копии чистой карты (круглые концы) + маркеры: обводка (`marker_outline_px`), диск, буква. Буква рисуется Pillow системным шрифтом (маска по реальным границам глифа — центрируется по «чернилам», а не по метрикам шрифта) либо `cv2.putText`, если `marker_font_path` пуст. SF Pro — вариативный файл `SFNS.ttf`, толщина выбирается именованным экземпляром (`set_variation_by_name`).
* **`reveal`** — накапливаемая маска кисти; итог = альфа-смешивание чистой и размеченной карт. Кисть линии = реальная толщина линии + запас. Каждый кружок — диск «синий диск + белое кольцо», измеренный по разнице картинок. Кружки, до которых линия ещё не дошла, **вырезаются из маски**: линия вплотную подходит к ещё скрытому кружку, затем он появляется целиком.

### Кадрирование и авто-масштаб
* `frame_crop` вырезает самую большую область с `output.aspect`, центрированную на bbox трека; затем `resize` до `output.resolution`.
* `autoscale_drawing`: коэффициент = медианный радиус найденных кружков / `marker_radius`; применяется к толщине линии, радиусу, обводке, шрифту (если отличается от 1 больше чем на 15 %).

### Кодирование
OpenCV-писатель в этой сборке **игнорирует любые настройки качества** (и даёт низкий битрейт), поэтому кадры (BGR, сырые) подаются в **ffmpeg** (`imageio-ffmpeg`, статическая сборка с libx264/libx265): `libx264 -crf 8…19 -preset slow`, `libx265 -crf 10…21`, `mpeg4 -q:v 1…5`; цвета маркируются **BT.709**, `yuv420p`, `+faststart`. Измерено: на 4K разница с «потолком» формата (4:2:0) ≈ 0,4 дБ. Если ffmpeg недоступен, используется `cv2.VideoWriter` с предупреждением. Размеры делаются чётными.

## 8. Сервер интерфейса (`ui.py`)

Стандартный `ThreadingHTTPServer` на `127.0.0.1:8765` (`MAP_ANIMATOR_PORT` меняет порт). Токен в HTML защищает API от посторонних страниц (`X-Token` или `?t=`).

| Маршрут | Метод | Назначение |
|---|---|---|
| `/`, `/docs`, `/docs/assets/*` | GET | страница; документация (README → HTML; язык из `?lang=`, затем из сохранённого языка интерфейса) и её картинки |
| `/api/defaults` | GET | значения из `config.json` + `DEFAULT_CONFIG` |
| `/api/settings` | GET/POST | запомненное состояние (`ui_settings.json`) |
| `/api/fonts`, `/api/codecs` | GET | системные шрифты (в т. ч. SF Pro), доступные кодеки |

Переменные окружения для тестов: `MAP_ANIMATOR_PORT`, `MAP_ANIMATOR_SETTINGS` (другой файл настроек), чтобы тесты не затрагивали работающее приложение и ваши настройки.

## 9. Страница (`ui_static/index.html`)

Один файл, ванильный JS, без сборки. Состояние: `cfg` (копия `config.json` + служебные ключи `__debug`, `__resPreset`), `styles`, `lang`, `uiScale`, сохраняются в `/api/settings` с задержкой 300 мс. Переводы — словарь `I18N`. Поля формы строятся из таблиц `MAIN` / `REDRAW_*` / `REVEAL` / `DETECT`; добавить параметр = добавить строку в таблицу + ключ в `I18N`. Превью — `<canvas>`; масштаб зависит только от карты (найденный радиус маркера) и уменьшается, если маркер или линия не помещаются.

## 10. Оболочка macOS

`launcher/MapAnimatorApp.swift` — SwiftUI-приложение: запускает `ui.py`, показывает `WKWebView`, окно документации, меню. **Почему не shell-скрипт в `.app`:** macOS проверяет доступ к «Загрузкам» по исполняемому файлу; у скрипта это `/bin/bash`, и разрешить доступ нельзя. Нативный бинарник имеет собственную идентичность. Сборка: `./build_app.sh` (`swiftc -parse-as-library`, иконка `AppIcon.icns`, подпись ad-hoc).

**Первый запуск:** если нет `.venv/bin/python` или сервер падает при старте из-за отсутствующих пакетов (проверка через `importlib.util.find_spec`), приложение показывает «Нужно установить компоненты», спрашивает *«Установить сейчас?»* и открывает `install.command` в Terminal; каждые 2 с оно перепроверяет и запускается само, когда установка закончена. Закрытие окна: если идёт генерация, приложение остаётся и выходит по её окончании; состояние `busy` кэшируется в фоне, чтобы закрытие не зависало.

Что проверено: названия официальные (владелец GitHub-репозитория каждого пакета — организация, которая стоит за библиотекой, то есть это не пакеты-двойники с похожим именем); скачанные файлы побайтно совпадают с опубликованными на PyPI (SHA-256); установленные файлы совпадают с хэшами, записанными при установке (3 847 файлов, изменённых нет); нет `sitecustomize`, единственный файл `.pth` — стандартный от setuptools; ни один пакет ничего не запускает при установке, потому что установщик берёт **только готовые wheel-файлы** (`--only-binary=:all:`, `setup.py` никакого пакета не выполняется); публичная база уязвимостей (OSV) **не знает уязвимостей** ни у одного из них, **кроме Pillow 11.3.0**.

*Pillow.* 36 записей, исправления есть только в Pillow 12.x, которому нужен Python 3.10+. Поэтому `requirements.txt` разрешает Pillow до 13: на Python 3.10+ pip поставит исправленную версию (проверено, что кадры на Python 3.12 с Pillow 12.3 и 13.0 совпадают бит в бит), а Python 3.9 (тот, что в инструментах Apple) остаётся на 11.3.0. На практике риск мал: приложение использует Pillow только для букв системными шрифтами и никогда не открывает им ваши карты (карты читает OpenCV). Установщик пишет предупреждение, если выбрал Python 3.9, и предпочитает более новый Python, если он есть.

*Код этого проекта:* не обращается ни к каким серверам, кроме `127.0.0.1`; страница не загружает внешних скриптов, шрифтов и картинок; установщик скачивает только пакеты с PyPI (и инструменты разработчика Apple, если вы согласитесь). Проверено, что видеокодер работает при отключённой сети.

*Честные ограничения:* проверка по открытым источникам не может доказать, что в пакет никогда ничего не попадало; она исключает типичные схемы обмана (похожие имена, подменённые файлы, неизвестные издатели) и известные уязвимости. ffmpeg внутри `imageio-ffmpeg` — готовый бинарник (статический, использует только системные библиотеки, подпись ad-hoc), пересобрать который мы не можем; чтобы взять свой ffmpeg, задайте `IMAGEIO_FFMPEG_EXE=/путь/к/ffmpeg`. `opencv-python` содержит собственные декодеры изображений, поэтому не открывайте файлы карт из ненадёжных источников. В сборке ffmpeg есть GPL-кодеки (x264/x265): он скачивается на вашем компьютере и не входит в образ диска.
